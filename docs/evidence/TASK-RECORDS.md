## Worked brownfield correction

**Intent:** introduce expiration without invalidating v1 creation requests. **Context:** v1 stored a hash of normalized URL/title/alias. **Rejected alternative:** unconditionally add a null expiry element to that hash; it changes existing keys' meaning. **Implemented revision:** retain the v1 representation when expiration is null, and include expiry only for expiring links. **Acceptance:** the legacy-fingerprint regression test must return the same original resource.

**Second correction:** a retry arriving after expiration must still return its original creation result. Rejecting past expiry before key lookup would violate that contract. The implemented service looks up/replays the key before validating a new resource's expiry; the expired-retry test verifies this order. The final code and tests verify these behaviors; an intermediate failing commit was not retained, so the exact initial faulty patch is not claimed as preserved.

## Worked current performance/evidence improvement

**Intent:** make the stated performance quality gate executable and bind validation to source. **Context:** the previous benchmark reported timings only; validation was mostly summarized in prose. **Constraints:** no hosted capacity claims, no external traffic, no secret/environment dumps. **Implemented revision:** assert every measured resolution returns the created resource; bound local p95 and total elapsed duration; retain command outputs, exit codes, Node version, source hashes and run time. **Acceptance:** normal verification passes; a deliberate threshold violation returns nonzero. Evidence records describe actual run outcomes only.
